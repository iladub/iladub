# [[R186]] — a proposal between the two surviving arms, and why the fork's own premise expired

**Written 2026-09-08**, on request, after the `two-loops-sequenced` judgement. **This is a
PROPOSAL to the maintainer, not a ruling** — CLAUDE.md is Contract-class and edited only on
explicit request. Nothing in `CLAUDE.md` is touched by this document.

**Authored at 1.3× the originating floor (~66k working tokens), override logged.** The reasoning is
short and every load-bearing claim is a measurement taken in this session, which is the mitigation;
§5 marks the one place it rests on n=2 instead.

**Doc impact: none.**

---

## 0. The verdict

**Take arm 3's WORDING, delete arm 3's RATIONALE, and fold arm 2's field back in at the granularity
the measurement demands.** Written as one line:

> **Evidence is append-only after loop close — never rewritten — and a file's `Doc impact:`
> declared VALUE is frozen outright.**

Both arms are partly right and each is wrong about the thing it was most confident about. Arm 3 has
the right sentence and a **false** justification. Arm 2 has the right instinct and the **wrong
granularity**. Neither is adoptable as written.

## 1. Arm 3's premise EXPIRED on 2026-08-31, and nobody noticed

Arm 3 says: rule that the norm is *unenforceable-by-design*, and concede it in CLAUDE.md.

**That premise is now false, and this repo falsified it itself.** The `two-loops-sequenced`
refutation of arm 1 was narrower than it reads: it kills any **time-windowed** rule, because the
date cannot separate loop iteration from post-close editing (73% vs 77% rewrite rates either side of
any clock). **A PR-boundary rule is not time-windowed, and the branch-protection ruling made the PR
boundary exact.**

Measured this session:

```
squash era begins after 5743af3 (2026-08-31)   # last merge commit = PR #145; #146+ are squashed
commits on main since the boundary                  32
of those, any PR contributing TWO commits            0     (one commit per PR, without exception)
```

So since 2026-08-31, **"a commit later than the introducing commit" IS "a later PR", exactly** — no
proxy, no grace window, no tuned constant. And the append/rewrite split is likewise exact, straight
off `--numstat`: deletions `> 0` is a rewrite.

Applied to the squash era:

```
squash-era Evidence files                           59
edited by a LATER PR                                 2
of those, pure APPEND (+N/-0)                        2      ← both
of those, REWRITE                                    0
```

Both cases, in full:

| file | later commit | shape |
| --- | --- | --- |
| `2026-09-02-the-body-starts-at-the-stub-handoff.md` | `4cfee38` | **+60 / −0** |
| `2026-09-08-release-v0-0-4-handoff.md` | `ac36e54` *"append the v0.0.4 release outcome — append, not rewrite"* | **+41 / −0** |

The second is the case this repo **consciously labelled** as R186's APPEND arm. A rule forbidding
*any* later edit fires on both — that is, on the one behaviour the repo has already ruled correct.
A rule forbidding *deletions by a later PR* fires on neither.

**This is why arm 3's wording is right and its rationale is wrong.** *"Append-only, and never
rewritten"* is not a resigned restatement of an unenforceable norm; **it is precisely and only the
predicate that a squash-merge regime can decide.** Arm 3 was drafted as a concession and turns out
to name the instrument. Adopt the sentence; strike the surrender.

## 2. Arm 2 freezes the right thing at the wrong granularity — measured, 14 to 0

Arm 2 says: the `Doc impact:` **declaration line** is immutable, the rest append-only.

Every post-introduction commit touching a `Doc impact:` line, swept across all 329 Evidence files:

```
post-introduction commits touching a `Doc impact:` line      14
of those, changing the declared VALUE (none/increment/contradiction)   0
```

All fourteen are one of three harmless kinds — an addition (the block written a commit after the
file), a **formatting normalisation** (`` `increment` `` → `increment`, `**contradiction.**` →
`contradiction.`, four separate times), or **prose after the keyword** with the value untouched
(`increment. Two published surfaces` → `increment. Larger than the first version stated`).

So arm 2 as written would have refused **14 real edits and prevented 0 defects.** The field is
right — it is the one thing the release gate reads (`scripts/release_gate.py`), and [[R185]] built
the drain register precisely so nobody needs to edit it. **The granularity is wrong: freeze the
declared VALUE, not the line.** At value granularity the rule is free — it has never once been
violated in this repo's history — and it still guards exactly what a release depends on.

## 3. Why arm 2 does not simply win on dominance

The tempting shortcut is *"arm 2 already contains arm 3's body rule plus a frozen field, so arm 2
dominates."* It does not, and the reason is worth stating once:

**Arm 3's distinctive content is not its body rule, it is its HONESTY about the norm's status** —
and the count showed why that matters. `265275d` breaks the rule and **says so in its own commit
subject** (*"three guards, and the rule broken while applying it"*), reasoning in prose about how
far it may go. That is not ignorance; it is **a norm being negotiated case by case because nobody
wrote down what it actually is.** Arm 2 leaves that half unstated and so leaves the negotiation
running.

The proposal keeps the honesty and inverts its content: CLAUDE.md should say plainly **what is
enforced, what is not, and why** — that the rule binds prospectively from the squash boundary,
because the 133 files and 229 events before it are not decidable by any instrument.

## 4. The proposed edit, stated so it can be refused precisely

In § Documentation governance, the Evidence clause currently reads *"immutable after loop close"*.
Replace with:

> **Evidence** (`docs/superpowers/**`, `docs/loops/**`, `docs/w3id/**`) — **append-only after loop
> close: a later PR may add, and may never delete or modify an existing line.** A file's
> `Doc impact:` **declared value** (`none | increment | contradiction`) is frozen outright — that is
> the one field a release reads, and [[R185]]'s drain register exists so it never needs editing.
> Two named exceptions as before (the register; a gated generated cache).
>
> **Binding prospectively, from `5743af3` (2026-08-31).** Before that boundary this repo merged with
> merge commits, and no instrument can separate loop iteration from post-close editing there — 229
> rewrite events across 133 files sit on the wrong side of a line nobody can draw. Since the
> boundary, one commit per PR makes "a later PR" exact and `--numstat` makes "deleted a line" exact.
> **This is the only reason the rule is now checkable, and it is checkable ONLY forward.**

**That prospective boundary is not a grace window and not a tuned constant** — the distinction
matters under CLAUDE.md § 8. It is a dated change in the merge regime, externally caused by the
branch-protection ruling, and it would be the same date whatever anyone wanted it to be.

## 5. What is NOT proven, and the honest way to refuse this

- **`0 rewrites in the squash era` is n=2.** Two later-PR events over eight days cannot show that
  rewriting stopped; the historical rate was 77%. **The claim this rests on is about the INSTRUMENT
  being well-defined, not about behaviour having improved.** If the next month produces squash-era
  rewrites, the rule starts refusing real work — and that is the outcome that should decide it, not
  this document.
- **`0 value changes in 14` is a full-history sweep and is the strong claim here.** It is the one
  number that would survive being wrong about everything else.
- **This proposal builds no lint.** It is a wording ruling. Whether the enforced half becomes a test
  is a separate question, and it belongs with [[R188]] — because a rule firing on zero is exactly
  the shape that row was raised about, and this one would fire on zero on day one.
- **The `two-loops-sequenced` evidence §1 should be read alongside this.** Its refutation of arm 1
  stands for time-windowed rules and **does not** reach the PR-boundary form; that narrowing is
  recorded here rather than by rewriting §1, which is the norm this document is about.
