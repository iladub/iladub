## 5. The next concrete action

Three, typed separately and independent of each other.

### 5a. PROPOSED — price R173's CI half by asking whether pytest can make a skip LOUD

**The prediction:** the remedy R173 has wanted since it was raised is a **summary that fails, or
at minimum warns, when a `pytest.mark.corpus` test is skipped in a run that expected it** — and
it is cheap, because the marker already exists and is now applied consistently (this loop removed
the one module-level mark that over-claimed). The shape to try first is a `--strict-corpus` style
flag or a `pytest_terminal_summary` hook in `conftest.py` that counts corpus skips and exits
non-zero when a CI-flavoured env var says the corpus should have been fetched.

**Why PROPOSED and not asserted:** nobody has checked whether `scripts/fetch_corpus.py` can even
run in CI (licensing of the third-party PDFs is an open question in CLAUDE.md's own Open items),
and *"make the skip loud"* has two incompatible readings — loud in CI, which needs the corpus, or
loud in the SUMMARY, which does not. **Decide which question you are answering before writing
anything**, and say so in the spec. If the corpus can never be in CI, the honest remedy may be a
committed, dated *census of what the corpus-gated tests last reported*, regenerated by a script
and gated by regenerate-and-diff — the generated-cache exception CLAUDE.md § Documentation
governance already allows.
