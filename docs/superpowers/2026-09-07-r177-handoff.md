## 5. The next concrete action

### 5a. PROPOSED — [[R179]]: make the membrane require what the emitter now writes

R177 existed for months because **nothing validated it**: `tab:EntryCellPhysicalShape` requires
`tab:hasBBox` on every `tab:EntryCell`, and no shape requires it on a `tab:LabelCell` (spec § 3.5,
`grep -rn "LabelCell" vocab/shapes/*.ttl` → one unrelated hit). The producer-side repair shipped
here is now the *sole* enforcement, on one branch, pinned by one test module.

**The prediction, and it is the falsifiable part:** that a `LabelCellPhysicalShape` can be added
**without changing a single corpus verdict**. The reading that would sink it: `region_tiles` runs
the tiling shapes over every candidate region at `compile.py:836,910,967,1023,1166`, so a new label
shape is not documentation — it is a **gate on what may assert at all**. If any of the six sibling
label emitters ever writes a boxless cell on a real document, adding the shape *escalates that
region*, and the "provenance fix" becomes a score regression.

**Run the cheap disposal first, and this loop has already built it**: add the shape, run
`scripts/unbooked_ink_fate_corpus.py`, and diff the per-page readings exactly as spec § 4.1 does.
If IDENTICAL, ship it. If not, the shape has found a second R177 on another branch — which is a
better outcome than shipping it, and should be reported as one rather than worked around.

**The design fork inside it, which must be taken before writing the shape:**
`span.build_reading` mints a `HeaderNode` for a column carrying **no header ink at all**, and
that node's LabelCell is *honestly* boxless. Either (a) `minCount 1` on all labels, and the flank
filler must stop being a `tab:LabelCell`; or (b) a conditional shape in `tab:WrappedCellShape`'s
style, firing only when the node it labels carries geometry. Do not write the shape before choosing
— (a) is a vocabulary change and (b) is not.

### 5b. PROPOSED — [[R178]] is now measured, and "not worth a loop" is a legitimate closure

The row's disposal is RUN (§ 1 below). Its population is **12 words in 2 of 7 documents**, not the
111 the blinded prober reported, and it is **two questions, not one**:

* the 3-word `Year: Month` caption — a **placement** question at the matrix site (ink belonging to
  neither axis);
* 9 items on graincorp-stem p0 — a date banner plus eight uncarried column-header fragments — a
  **coverage** question at the hierarchical site, on a band whose other 17 header cells *were*

**The prediction:** that these do not share a repair, so any single rule proposed for "the orphans"
is the wrong shape. **What would sink it:** finding that the graincorp fragments are uncarried for
the same reason the caption is — i.e. both are ink whose position the header tree has no node for —
in which case one coverage rule does cover both.

**And the disposition worth naming out loud**: 12 words across 2 documents may not justify a reading
change at all. Closing R178 as *measured and not worth carrying* is a legitimate outcome, and the
measurement to support it now exists. Do not treat "the row is open" as a reason to build.

**Falsification 5 is the one the other four cannot reach.** F1–F4 all attack the *positive* half —
that a node with geometry gets a box. Only F5 attacks the presence test itself, and it is the
mutation a reviewer would expect to be harmless: defaulting an absent bound to zero. It turns
`span.build_reading`'s ink-less flank node into a cell claiming a location the source never carried,
and — because `tab:WrappedCellShape` fires only on cells that carry a box — into a membrane
violation that `region_tiles` would convert into a refusal to assert.

**Falsification 4 is the one worth reading for a different reason.** That edit looks like tidying — the old line listed
every field it copied, and listed them correctly *at the time*. Reverting it drops the five new
fields one line after they were read and fails all three pins. It is the difference between fixing
this defect and fixing it in a way that cannot silently recur.
