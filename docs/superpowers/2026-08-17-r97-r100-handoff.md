to the guard, not an adjudication. Decide in the spec whether it belongs in this loop at all.

## Unverified or assumed

* **Whether R97–R99 are closable at all in one loop is unknown, and it is the first thing the
  spec must confront.** All three close on *specimens the corpus does not contain* or on a
  decision to delete. If the answer for all four `tab:` shapes is "we need documents we do not
  have", the loop's real deliverable is a deletion decision plus a corpus-acquisition residue —
  which is a legitimate outcome, but a different loop from the one the title implies. **Do not
  discover this halfway through.**
* **The guard bites back on any close that makes a shape live.** `test_no_registered_shape_has_gone_live`
  (`:337`) FAILS while a now-live shape still has its registry row. Every closing change is
  therefore two edits — the shape and its row — and the guard will catch you if you forget the
  second. Named in R97's row. Verify the exact failure mode before writing the plan; the
  assertion is at `:345`.
* **The pySHACL leg has never run against `540e608`, let alone `09449e4`.** It was green once at
  `d1e5ab1`'s tree, which differs only in docs. Every figure in R87 and in these four rows is
  the **rudof** leg (`membrane.py:19`; corrected in `e3073e5`, and earlier commits on that
  branch say the reverse). Running the other leg before designing is cheap and would either
  confirm the four counts or produce the loop's first finding.
* **R100's cost is asserted, not measured.** Its row says keying by (shape, leg) "doubles every
  row and changes the seed the plan specifies". Nobody has counted what that actually costs, and
  its own row names the cheaper alternative — measure whether *any* other wired shape's liveness
  differs by leg. If none does, the (shape, leg) key is unnecessary and R100 closes without a
  guard change. **Measure that before designing the key.**
* **The four `tab:` shapes of R97 are treated as one row in the index and four in the registry.**
  Whether they adjudicate together or separately is undecided. `tab:BaseFactShape` in particular
  now has a consumer it did not have when R97 was raised — `09449e4` landed the 1NF export leg
  and `tests/test_zero_etl_export.py` exercises base facts end to end. **Nobody has checked
  whether that test's graph gives `tab:BaseFactShape` a focus node**; if it does, R97 is already
  one-quarter closed and the registry row is stale. This is the single cheapest measurement in
  this handoff and it was not run.
* **Scope creep risk, named:** R99 opens "which membrane should this shape be on", which is a
  composition question with no natural boundary. R87's own spec declined to open it. If the spec
  takes R99, it must state where the composition question stops.

## Constraints that bind this loop

Not assumptions — repo rules, listed because they change the shape of the answer:

* **The neurosymbolic gate (CLAUDE.md §8).** A shape is an AXIOM/constraint artefact; any
  adjudication that reaches for Python to decide liveness is a defect. The guard is already
  SPARQL-over-graphs and should stay that way.
* **Plan-authoring discipline (CLAUDE.md, rules 1–5).** Rule 5 especially: a plan-supplied test
  must be reconciled against the spec's "what is NOT done" section. This loop is *made* of
  things a previous spec scoped out, so that reconciliation is not a formality here.
* **A loop is a session.** The spec goes in a fresh one.
